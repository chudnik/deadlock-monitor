# Deadlock Monitor

**Deadlock Monitor** — учебный проект на C++20 для моделирования распределения нескольких типов ресурсов между потоками. Для предотвращения взаимных блокировок используется **алгоритм Банкира**.

Проект демонстрирует:

- потокобезопасный монитор ресурсов;
- поддержку нескольких типов ресурсов;
- проверку безопасного состояния алгоритмом Банкира;
- блокировку потоков на `std::condition_variable`;
- асинхронное логирование;
- финальную статистику по потокам;
- проверку внутренних инвариантов монитора;
- простые автоматические тесты через CTest.

---

## Идея проекта

В системе есть общий пул ресурсов, например:

```text
[10, 5, 7]
```

Это означает, что есть три типа ресурсов:

```text
ресурс 0: 10 единиц
ресурс 1: 5 единиц
ресурс 2: 7 единиц
```

Каждый поток заранее имеет максимальную потребность `max_claims`. Например:

```text
Thread 0: [7, 5, 3]
Thread 1: [3, 2, 2]
Thread 2: [9, 0, 2]
```

Когда поток делает запрос, монитор временно выделяет ресурсы и проверяет, останется ли система в безопасном состоянии. Если безопасная последовательность завершения потоков существует, запрос разрешается. Если нет — поток блокируется.

---

## Модель симуляции

В текущей версии используется **классическая модель алгоритма Банкира**:

1. поток постепенно запрашивает ресурсы;
2. ресурсы накапливаются в `allocation`;
3. когда `need` потока становится нулевым, поток вызывает `finish(thread_id)`;
4. `finish()` возвращает все ресурсы потока в общий пул и помечает поток завершенным.

Метод `release()` тоже оставлен в проекте. Он нужен для частичного возврата ресурсов и для аккуратной остановки потока при `shutdown()`, но основной сценарий симуляции использует `finish()`.

## Основные события логгера

| Событие | Значение |
|---|---|
| `REQUEST` | Поток запросил ресурсы |
| `GRANTED` | Запрос был успешно выдан сразу |
| `BLOCKED` | Ресурсов физически не хватает, поток ждёт |
| `DENIED` | Ресурсы есть, но выдача сделала бы состояние небезопасным |
| `WAKEUP` | Ожидающий поток получил ресурсы после освобождения ресурсов другим потоком |
| `RELEASE` | Поток частично вернул ресурсы |
| `FINISH` | Поток завершился и вернул все ресурсы |
| `COMPLETE` | Worker завершил работу после `finish()` |
| `CANCELLED` | Запрос/работа потока отменены из-за остановки симуляции |

## Запуск

Формат запуска:

```bash
./deadlock_monitor <threads> <duration_sec> <resource_1_total> [resource_2_total ...]
```

Пример:

```bash
./deadlock_monitor 5 10 10 5 7
```

Это означает:

```text
5 потоков
10 секунд симуляции
ресурсы: [10, 5, 7]
```

## Ключевые классы

### `ResourceMonitor`

Главный класс проекта. Отвечает за:

- хранение `available`, `allocation`, `need`;
- проверку безопасного состояния;
- обработку `request()`;
- частичный возврат через `release()`;
- окончательное завершение через `finish()`;
- остановку через `shutdown()`;
- проверку инвариантов через `checkInvariants()`.

### `Logger`

Асинхронный логгер. Сообщения помещаются в очередь, а отдельный поток печатает их в консоль. Метод `flush()` ждёт, пока очередь станет пустой и последнее сообщение будет допечатано. Это нужно, чтобы статистика не смешивалась с логами.

### `LogFormatter`

Отдельный класс форматирования. Он преобразует `ResourceVector`, `ResourceMatrix` и `StateSnapshot` в строки.

### `resource_utils`

Набор функций для работы с ресурсными векторами:

- `lessOrEqual()`;
- `addTo()`;
- `subtractFrom()`;
- `isZeroVector()`;
- `makeZeroVector()`.

## Инварианты монитора

Монитор проверяет, что ресурсы не исчезают и не появляются из ниоткуда:

```text
available[j] + sum(allocation[i][j]) == total[j]
```

Для незавершённых потоков также должно выполняться:

```text
allocation[i][j] + need[i][j] == max_claims[i][j]
```

Для завершённых потоков:

```text
allocation[i] == [0, 0, ...]
need[i] == [0, 0, ...]
```
